## 1. 插件层设计（MCP 语义，进程内实现）

### 1.1 插件协议

```python
@dataclass
class PluginResult:
    ok: bool
    data: dict          # 成功时的结构化结果
    error: str = ""     # 失败原因（给日志，不进用户消息）

class Plugin(Protocol):
    name: str           # 唯一名，如 "play_music" / "get_joke"
    description: str    # 一句话说明（对齐 MCP tool description）
    parameters: dict    # JSON Schema 风格的参数说明（对齐 MCP inputSchema）
    def run(self, args: dict) -> PluginResult: ...
```

注册表：`xncagent/tools/registry.py`，`register(plugin)` / `get(name)` / `list_tools()`（返回 tools/list 结构）。

**面试口径**：工具层抽象按 MCP 协议设计，一期进程内实现（零网络开销、离线可演示）；二期换成真实 MCP Server 时，Agent 侧只改 registry 的实现来源，调用方零改动——适配器模式，工具的可替换性是一等设计目标。

### 1.2 一期插件清单


| 插件           | 触发方式                   | 说明                   |
| ------------ | ---------------------- | -------------------- |
| `play_music` | Agent 规则触发（§2）         | 场景 + 概率 → 查设置 → 曲库选歌 |
| `get_joke`   | Agent 规则触发（求笑话/活跃气氛场景） | 现有 apictl 接口迁入插件层    |


一期**不做** LLM tool call（无 function calling、无 ReAct 循环）：LLM 负责"感知"（scene），规则负责"执行"（调哪个插件）。演进路径：二期 LLM 直接输出工具选择（ReAct），规则触发退化为降级通道。

## 2. 场景音乐链路

```
understand 已有 scene（LLM 输出 / bge 降级接管）
    │
    ├─ emotion_alert（安全树洞）触发 ────→ 静默跳过（树洞协议最高优先级，只沉默陪伴）
    ├─ scene 未配置音乐（含"无关闲聊"）─→ 静默跳过
    ├─ 概率抽签未中 ────────────────────→ 静默跳过
    ├─ 查 user_settings：music_enabled = false → 静默跳过（零提示，不影响对话）
    └─ 全部通过：
        play_music.run({"scene": scene})
            ├─ 查 music_library.yaml 该场景候选列表
            ├─ 随机取一首（同一会话内避免连续重复）
            └─ 返回 {title, url, scene, reason, notice}
        → SSE meta 帧下发 → 前端气泡 + 播放器
```

返回字段（2026-10-02 修订）：`reason` 为应答文案（含《歌名》，文案从 `reason_templates` 列表随机抽取，支持 `{title}` 占位符，列表为空回退固定模板）；`notice` 固定为「（将使用网络流量播放）」，前端单独灰斜体渲染，不再拼在 reason 末尾。

延迟账：一次 YAML 内存查询 + 一次设置表查询 + 随机数，毫秒级。LLM 调用数不变，用户无感知。

### 2.1 曲库清单（`xncagent/config/music_library.yaml`）

已录入 5 场景 14 首（2026-10-02），结构示例：

```yaml
probability:
  default: 0.3            # 全局默认，可按场景覆盖；二期接用户画像动态调整

reason_templates:          # 随机应答库：触发后随机抽一条，支持 {title} 占位符；缺省回退固定模板
  - "主子聊到这茬，奴才斗胆配个曲儿——《{title}》"
  - "奴才翻出《{title}》，给主子垫一句。"

scene_music:
  职场吐槽:
    - file: 职场吐槽/xxx.mp3     # 本地形态：frontend/public/music/ 下相对路径
      title: ...
      artist: ...
    - url: https://.../xxx.mp3  # 外链形态：生产用，插件层无感知
      title: ...
      artist: ...
```

清单加载失败 → 插件返回 `ok=False`，**不打断主链路**（同召回失败口径）。

### 2.2 设置存储（`user_settings` 表，migrate_0005）

```sql
CREATE TABLE user_settings (
    user_id       INT PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,  -- 用户 ID
    music_enabled BOOLEAN NOT NULL DEFAULT TRUE,   -- 音乐播放开关（使用网络流量）
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
COMMENT ON TABLE user_settings IS '用户设置表：前端零状态，本表为唯一权威';
```

- 匿名用户不查表，按默认（开）处理——与历史/召回的匿名口径一致（无归属不个性化）；
- migrate_0005 放 Go 仓 `deploy/postgres/`（initdb.d 自动执行）；若 Python 仓存在迁移镜像文件需同步；
- 查询走"无则插默认值"的 upsert 读取（`INSERT ... ON CONFLICT DO NOTHING` 后 SELECT），保证老用户无行时也能读到默认 true。

### 2.3 设置 API（Agent 域）


| 方法  | 路径                | 说明                                             |
| --- | ----------------- | ---------------------------------------------- |
| GET | `/agent/settings` | 读当前用户设置（无行返回默认 `{music_enabled: true}`；匿名返回默认） |
| PUT | `/agent/settings` | 更新 `{music_enabled: bool}`，upsert；匿名 401       |


前端设置面板：点开时 GET，拨动开关时 PUT；**不写 localStorage**。

### 2.4 生产存储形态（部署决策待定）


| 方案                      | 优点        | 代价           |
| ----------------------- | --------- | ------------ |
| 第三方平台直链（可直接访问的 mp3 URL） | 零带宽成本、零存储 | 链接失效不可控、版权灰色 |
| 自建 OSS + CDN            | 稳定、可控     | 存储+流量按量付费    |


插件层两种形态都支持（YAML 里 `file`/`url` 二选一），决策不影响代码；ECS 部署前定即可。面试口径：「音频是读多写少的静态资源，不属于应用服务器；存储形态是部署期决策，配置切换即可，架构层面已解耦」。

### 2.5 SSE meta 帧

在现有 token 帧之前发送一帧：

```
event: meta
data: {"music": {"title": "加班布鲁斯", "url": "/music/职场吐槽/xxx.mp3", "scene": "职场吐槽", "reason": "奴才翻出《加班布鲁斯》，给主子垫一句。", "notice": "（将使用网络流量播放）"}}
```

- 文案由后端拼好，前端不做文案逻辑；`notice` 独立字段，前端以灰斜体单独渲染（2026-10-02 修订，之前 notice 拼在 reason 末尾）；
- EventSource 按事件名分发，旧前端代码只监听默认事件、**自动忽略 meta 帧**，前后端可分上线。

## 3. 前端交互

> 原则：**meta 帧只是数据，展示位置由各端自己决定**。同一份 meta 帧，不同设备渲染为不同形态。

| 设备 | 形态 |
|------|------|
| 桌面端（宽度 >768px 且非触屏） | 小人图标（右下角）上方弹气泡，文案用后端 `reason`；气泡旁出原生 `<audio controls src=url>` 控件，可关闭（关闭仅隐藏，不暂停后端逻辑） |
| 触屏 / 小屏（宽度 ≤768px **或** `pointer: coarse`，覆盖 h5、iPad、iPhone） | 音乐渲染为**聊天流中的特殊消息卡片**：小喜子头像 + `reason` 文案 + 内嵌 `<audio>` 控件，随消息列表滚动；**卡片滚出视口后浮现可拖动的迷你播放器**（详见下方"迷你播放器"） |

说明：

1. **设置面板**：侧边栏齿轮图标（`public/setting.png`），与"在线"状态同区；点开为设置面板，首项"音乐播放"开关（注明"播放将使用网络流量"），状态完全来自后端 API（§2.3），不写 localStorage；面板框架预留多格。
2. 触屏形态的音乐卡片作为**伪消息**进入按 session_id 索引的全局消息 store：切换会话再切回卡片仍在（浮层气泡做不到这一点）；刷新页面后消失（音乐消息不落库），属明确不做项。

**迷你播放器（触屏形态专属）**：

- 出现条件：`IntersectionObserver` 检测到音乐卡片滚出视口、且该曲目尚未被用户关闭 → 浮现悬浮迷你播放器；卡片滚回可见 → 悬浮条自动隐藏（不与卡片控制条同时出现）；
- 内容：曲名 + 播放/暂停 + 关闭；**可拖放到屏幕任意位置**（Pointer 事件实现，拖动手势与页面滚动手势做阈值区分，不拦截聊天滚动）；
- 位置只存组件内存态，刷新重置（符合"前端不存业务状态"原则）；
- 同一会话命中多首时，悬浮条始终绑定**最近一首**，同时只有一个悬浮条。
3. 未收到 meta 帧 → 界面无任何变化。

## 5. 坑点提示

1. **本设计不新增 LLM 输出字段**（scene 已有）——v1 的 `emotion_label` 及其默认值坑一并取消。
2. 设置查询失败（表不存在/连接闪断）→ 按默认"开"处理并记 WARN，**不因设置查询失败阻断主链路**（宁可多播一首歌，不可卡聊）。
3. 概率抽签与设置查询放在**生成前**（与召回同级），全部失败静默。
4. 音乐插件纯本地实现：YAML + 设置表 + 随机数，无外部网络调用。

## 6. 验收用例

1. 概率置 1：发职场吐槽话题 → 收到 meta 帧，气泡出现，播放器能出声；
2. 概率置 0：同场景 → 无 meta 帧，界面无变化；
3. PUT `/agent/settings` 关音乐 → 发已配置场景的话 → 无 meta 帧，后端日志可见设置关闭；GET 读回 false；重新打开后恢复播放；
4. 匿名用户发已配置场景的话 → 按默认开处理（如播则播，行为符合默认）；
5. 连续两次极度负面（树洞触发）→ **不弹气泡**，进入沉默陪伴；
6. 发"无关闲聊"类对话 → 无 meta 帧；
7. 删除/改名 music_library.yaml 后发已配置场景的话 → 对话正常，日志有插件失败记录；
8. 同一会话连续两次命中同场景（概率置 1）→ 不重复同一首；
9. `url` 形态歌曲（临时把某首指到外链）→ 播放器照常出声；
10. 触屏形态（h5 宽度或 DevTools 模拟触屏）：音乐卡片插入聊天流正常；滚动使卡片离开视口 → 迷你播放器浮现、可拖动、暂停/播放生效；滚回卡片处 → 悬浮条自动隐藏。

## 7. 明确不做

- LLM tool call / ReAct 循环（二期）；
- 真实 MCP Server 进程（二期，registry 换实现即可）；
- 第三方音乐 API（已否决，见 §0）；
- 概率接用户画像（二期：画像 → 动态概率，配置结构已预留）；
- 音乐推荐个性化（播放历史加权等，属二期 Recommend 范畴）；
- 设置项多端同步之外的复杂偏好体系（现仅一开关，表结构按需扩列）。
