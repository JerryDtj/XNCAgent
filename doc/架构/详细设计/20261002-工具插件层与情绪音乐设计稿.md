## 0. 决议（D1–D4）

| # | 议题 | 决议 |
|---|------|------|
| D1 | 插件层形态 | 进程内插件注册表，接口语义对齐 MCP（`tools/list` + `tools/call`）；`get_joke` 迁入。二期可换真实 MCP Server（stdio/SSE），Agent 侧调用代码零改动 |
| D2 | 情绪标签 | LLM 统一调用输出新增 `emotion_label: str = ""`（`happy` / `sad` / `tired` / `calm` / 空 = 无明确情绪）；插件由 Agent **规则触发**（非 LLM tool call），二期再上 ReAct |
| D3 | 曲库 | 本地 mp3（`XNCAgent-frontend/public/music/`）+ 标签清单 `xncagent/config/music_library.yaml`。歌曲用 CC 协议无版权素材（Free Music Archive / Pixabay Music / Musopen），**禁止有版权歌曲入库**（会进 GitHub） |
| D4 | 下发通道 | SSE 在 token 流之前加一帧 `event: meta`（JSON），前端解析后弹气泡 + 播放控件 |

否决记录：网易云非官方 API 因 VIP 试听限制（非会员只能听片段）直接伤害情感陪伴体验，且接口非官方、URL 过期、版权灰色——不作为一期依赖，也不作为二期默认实现。

## 1. 插件层设计（MCP 语义，进程内实现）

### 1.1 插件协议

```python
@dataclass
class PluginResult:
    ok: bool
    data: dict          # 成功时的结构化结果
    error: str = ""     # 失败原因（给日志，不进用户消息）

class Plugin(Protocol):
    name: str           # 唯一名，如 "play_music" / "get_joke"
    description: str    # 一句话说明（对齐 MCP tool description）
    parameters: dict    # JSON Schema 风格的参数说明（对齐 MCP inputSchema）
    def run(self, args: dict) -> PluginResult: ...
```

注册表：`xncagent/tools/registry.py`，`register(plugin)` / `get(name)` / `list_tools()`（返回 tools/list 结构）。

**面试口径**：工具层抽象按 MCP 协议设计，一期进程内实现（零网络开销、离线可演示）；二期换成真实 MCP Server 时，Agent 侧只改 registry 的实现来源，调用方零改动——适配器模式，工具的可替换性是一等设计目标。

### 1.2 一期插件清单

| 插件 | 触发方式 | 说明 |
|------|----------|------|
| `play_music` | Agent 规则触发（§2） | 情绪 → 标签 → 本地曲库选歌 |
| `get_joke` | Agent 规则触发（闲聊/求笑话场景） | 现有 apihz 接口迁入插件层，README 标注的"规划中"落地 |

一期**不做** LLM tool call（无 function calling、无 ReAct 循环）：由 LLM 负责"感知"（emotion_label、scene），由规则负责"执行"（调哪个插件）。演进路径：二期 LLM 直接输出工具选择（ReAct），规则触发退化为降级通道。

## 2. 情绪音乐链路

```
understand 输出新增 emotion_label: str = ""
    │
    ├─ emotion_label 为空 ─────────────→ 不触发（零开销）
    ├─ 安全树洞触发（emotion_alert）─────→ 不触发（树洞协议最高优先级，只沉默陪伴）
    └─ 有明确情绪：
        play_music.run({"emotion": emotion_label})
            ├─ emotion → 同义词组映射（YAML 可配：happy→[happy,欢快,明亮]）
            ├─ 按标签过滤候选（music_library.yaml）
            ├─ 随机取一首（同一会话内避免连续重复）
            └─ 返回 {title, url: "/music/<file>", reason}
        → SSE meta 帧下发 → 前端气泡 + 播放器
```

### 2.1 曲库清单（`xncagent/config/music_library.yaml`）

```yaml
# 标签维度与 emotion_label 对齐，一首歌可挂多个标签
songs:
  - file: sunny_walk.mp3        # 对应 frontend/public/music/sunny_walk.mp3
    title: 晴天散步
    artist: <作者>
    tags: [happy, calm]
  - file: rain_window.mp3
    title: 雨敲窗
    artist: <作者>
    tags: [sad, tired]

# 情绪 → 标签同义词组，调口味不改代码
emotion_tags:
  happy: [happy]
  sad: [sad]
  tired: [tired, calm]
  calm: [calm]
```

一期规模 8–12 首、4 种情绪各 2–3 首即可。清单加载失败（文件缺失/格式错）→ 插件返回 `ok=False`，**不打断主链路**（同召回失败口径）。

### 2.2 SSE meta 帧

在现有 token 帧之前发送一帧：

```
event: meta
data: {"music": {"title": "雨敲窗", "url": "/music/rain_window.mp3", "emotion": "sad", "reason": "检测到主子有些 emo，一起来听一首《雨敲窗》吧"}}

```

兼容要求：前端 EventSource 只监听默认 `message` 事件的旧代码**自动忽略** `meta` 帧（EventSource 按 event 名分发，无名事件才进 onmessage），因此该改动对旧前端无感、可灰度。

## 3. 前端交互

1. 收到 meta 帧 → 在小人图标（右下角 xnc.png）上方弹气泡，文案用后端 `reason`（后端拼好文案，前端不做文案逻辑）；
2. 气泡旁/下方出原生 `<audio controls src=url>` 播放控件，可手动关闭（关闭仅隐藏控件，不暂停后端任何逻辑）；
3. 未收到 meta 帧时界面无任何变化。

## 4. 安全机制（独立成节，面试材料补齐）

> 现状已落地，本节为归纳，不含新开发。

| 层 | 措施 | 状态 |
|----|------|------|
| 输入层 | 长度截断（>512 字符）、敏感词正则黑名单 | 已落地 |
| 模型层 | 系统提示词角色边界；LLM 统一调用单点可控 | 已落地 |
| 情绪安全 | emotion_alert → 安全树洞协议：连续极度负面 → 终止玩笑、沉默陪伴（**最高优先级，高于一切记忆与插件**） | 已落地 |
| 输出层 | 错误脱敏（统一兜底话术，不泄露堆栈/密钥/模型名）；依赖上游内容安全 | 已落地 |
| 传输/认证 | JWT + refresh Cookie 旋转；会话接口越权 404 防枚举 | 已落地 |
| V2 规划 | Prompt Injection 本地检测、滑动窗口限流、输出二次审核、安全审计日志 | 规划中（见架构演进 §2.0 改进 5） |

## 5. Schema 与坑点

1. `RewriterQuestionResponse` 新增 `emotion_label: str = ""`——**必须给默认值**，并沿用 `recall_query` 的 None→空串 validator 套路（同一类静默事故：校验失败 → 整轮掉进降级通道）。
2. understand 提示词 JSON 约定同步加 `emotion_label`：只对**明确的情绪表达**打标（开心/难过/累/平静），普通陈述、提问一律空串——宁可漏标（少播一首歌）不可误标（树洞场景播歌是事故）。
3. 音乐插件纯本地实现：读 YAML + 随机选择，无网络调用、无 I/O 阻塞，失败只记日志。

## 6. 验收用例

1. 发「哈哈哈今天也太开心了」→ 收到 meta 帧，气泡出现 happy 文案，播放器能出声；
2. 发「好累，什么都不想干」→ tired 歌曲；
3. 连续两次极度负面（树洞触发）→ **不弹气泡**，进入沉默陪伴；
4. 发「1+1 等于几」→ 无 meta 帧，界面无变化；
5. 删除/改名 music_library.yaml 后发开心话 → 对话正常，日志有插件失败记录；
6. 会话内连续两次触发 happy → 不重复同一首。

## 7. 明确不做

- LLM tool call / ReAct 循环（二期）；
- 真实 MCP Server 进程（二期，registry 换实现即可）；
- 第三方音乐 API（体验与版权不可控，已否决）；
- 音乐推荐个性化（播放历史加权等，属二期 Recommend 范畴）。
