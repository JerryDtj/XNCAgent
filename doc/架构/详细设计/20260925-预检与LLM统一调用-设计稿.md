### 函数签名

```python
def needs_rewrite(query: str) -> bool:
    """
    规则预检：判断 query 是否需要进入 LLM 改写分支。

    纯字符串匹配，零 LLM 成本。
    命中任一类别词表 → True（带历史进 LLM 统一调用）；
    未命中 → False（不带历史进 LLM 统一调用）。

    注意：单字词（如"呢"）需要做词边界判断，
    要求前后字符不是中文/字母/数字，避免"好呢""嗯呢"误触发。
    """
```

### 实现要点

- 词表在模块导入时加载一次，常驻内存；
- 匹配前归一化：去空白、小写（英文词如"emo"不受影响）；
- 每次判定记 DEBUG 日志：命中了哪个词、属于哪个类别——词表迭代全靠这份日志；
- 单字词边界规则与讨论中废弃的快路径实现相同，可复用思路。

## 任务 3：LLM 统一调用（改写 + 场景识别，一次调用）

### 函数签名

```python
SCENE_WHITELIST = ["挨骂兜底", "安慰话术", "懒懒不想动", "捧哏金句", "职场吐槽"]

def understand_query(query: str, history: str = "") -> dict:
    """
    一次 LLM 调用，同时完成改写与场景识别。

    :param query: 用户原始输入
    :param history: 预检命中时传入的最近 N 轮对话（预检未命中时为空串）
    :return: {
        "rewritten_query": str,   # 改写后的完整问题；自包含时原样返回
        "scene": str,             # 6 值之一：5 个场景白名单 + "无关闲聊"
        "emotion_alert": bool,    # 极度负面情绪预警（树洞双保险的第一道）
        "confidence": float,      # 模型自报置信度，只记日志不参与决策
    }
    调用失败抛异常，由调用方兜底（返回兜底话术 + 记日志）。
    """
```

### 返回结构说明

| 字段 | 用途 | 消费方 |
| --- | --- | --- |
| `rewritten_query` | RAG 检索用词（补全指代后召回更准） | RAG 检索 + 生成 prompt |
| `scene` | RAG 过滤依据 | 白名单校验 → 合法则按 file_name 精准检索 |
| `emotion_alert` | 树洞双保险第一道 | true 时对原文跑正则校验，确认才触发安全协议 |
| `confidence` | 观测用 | 只写日志，攒数据验证后再决定是否参与决策 |

### scene 取值与路由

- `scene ∈ SCENE_WHITELIST`（5 个之一）→ 按 file_name + version 精准检索 RAG；
- `scene == "无关闲聊"` → 跳过 RAG，直走 LLM；
- JSON 解析失败 / scene 不在枚举内 → 跳过 RAG，用原始 query 直走 LLM
  （兜底决议：话术库小，RAG 误配是"误导"，宁可朴素不可误导）。

### Prompt 草案（完整文本）

````text
你是一个查询理解与改写助手，服务于一个名叫"小喜子"的太监人设闲聊 agent。
小喜子用幽默夸张的话术陪主人聊天，你的话术库存放在知识库中，按场景分文件存放。

## 任务

分析用户的当前输入，完成以下三件事：

1. **改写**：如果输入自包含、没有歧义，`rewritten_query` 原样返回。
   如果包含指代、省略、反问，或依赖对话上下文，请结合对话历史，
   把它补全为一个中立、完整、可以独立理解的问题（反问句要转成客观陈述，
   但保留用户原本的情绪倾向）。

2. **场景识别**：判断输入属于以下哪种场景。**必须**从列表中选一个，
   不允许创造列表外的新场景：

   - 挨骂兜底：主人吐槽小喜子本人（如"你好贱""想打你""闭嘴"）
   - 安慰话术：主人 emo、自我怀疑、情绪低落、人际敏感，需要安慰共情
   - 懒懒不想动：主人说"不想动""不想起""只想躺着"、赖床、早八起不来
   - 捧哏金句：主人大笑（"哈哈哈""笑死"），需要接梗捧哏
   - 职场吐槽：主人吐槽上班、开会、老板、甲方、加班
   - 无关闲聊：以上都不属于的日常闲聊

3. **情绪预警**：如果主人表达了极度负面情绪（如"烦死了""想哭""没意思"
   "不想活了"），将 `emotion_alert` 置为 true，否则置为 false。
   注意区分"主人自己难受"和"主人转述别人难受"，只有前者置 true。

## 输出格式

严格输出 JSON，不要输出任何其他内容：

{
  "rewritten_query": "...",
  "scene": "...",
  "emotion_alert": false,
  "confidence": 0.0
}

confidence 是你对自己判断的把握程度（0 到 1 之间的小数）。

## 对话历史

{history}

## 用户输入

{query}
````

### 调用参数与容错

| 项 | 取值 | 说明 |
| --- | --- | --- |
| model | `llm_config.yaml` 中配置的对话模型（agicto deepseek 系） | 与生成环节同一模型 |
| temperature | 0 | 改写要稳定，示例代码同款 |
| 超时 | 建议 15s，可配 | 云端 API |
| 重试 | JSON 解析失败时重试 1 次（追加"请只输出 JSON"） | 仍失败走兜底 |
| 兜底 | 返回预设话术"系统开小差了"，记 ERROR 日志 | 不暴露原始错误 |

### 树洞双保险（emotion_alert 消费方）

`emotion_alert == true` 时，对**原文**再跑一次正则校验
（强信号词："不想活了""想死""自杀"等），命中才确认触发 system prompt 的
安全树洞协议；确认不了按普通安慰话术处理。触发与校验结果都记日志。

### 日志字段（每次调用必记）

`query, rewritten_query, scene, emotion_alert, confidence, latency_ms,
history_included(bool), 重试次数`——confidence 的验证、词表迭代、
树洞复盘全靠这份日志。

## 与主链路的衔接（对应 task_check）

```
query ──→ needs_rewrite(query) ──┬─ True  → understand_query(query, history)
                                 └─ False → understand_query(query)
                   ↓
        scene 合法？── 是 → RAG 按 file_name 精准检索 → 拼 prompt → LLM 生成
                   └── 否 → 跳过 RAG，原始 query 直走 LLM 生成
```

### 用户身份：请求头 `X-User-Id`（2026-09-25 补记）

登录在 Go 网关完成。Python Agent 不解析 JWT，也不回调用户服务。网关验签后，反代到 Agent 时带上请求头：

| 头 | 值 | 缺省 |
| --- | --- | --- |
| `X-User-Id` | JWT 里的 `user_id`，十进制数字 | 无此头，或不是纯数字 → 视为未带用户 |

Python 侧与现有 `X-Request-ID` 同一方式：中间件读头，写入 `ContextVar`；`task_check` 通过 `get_user_id()` 取值。

- 预检命中且 `user_id` 存在：用它读 L0 当前窗口（`chat:window:{user_id}`），拼成 `history` 再调 `understand_query`。
- 预检未命中，或没有 `user_id`，或窗口为空：`history` 为空串。

网关反代尚未接入时，直接请求 Python 可以不带此头，理解链路仍按无历史运行。身份以 `X-User-Id` 为准；`Authorization` 即使被透传，Agent 也不再解一遍 token。
