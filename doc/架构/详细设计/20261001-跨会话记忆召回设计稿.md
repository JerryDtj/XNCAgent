# 20261001-跨会话记忆召回设计稿

> 状态：待邓天骄定稿
> 前置：[20260928-会话与历史记忆设计稿](./20260928-会话与历史记忆设计稿.md)（消息落库 / L0 / 语义搜索已落地）
> 动机：L0 只加载**当前会话**最近 5 轮，用户在 B 会话问 A 会话聊过的内容（"你还记得我吗""我喜欢谁"），主链路无任何环节能提供旧会话上下文。本设计让 agent 主动回忆。

## 0. 三级记忆体系（面试口径骨架）

| 层级 | 名称 | 数据源 | 范围 | 状态 |
|------|------|--------|------|------|
| L0 | 当前会话窗口 | Postgres 当前 session 最近 5 轮 | 当前会话 | 已落地 |
| L1 | 跨会话向量召回 | chroma `chat_history`，按 recall_query 检索 | 全部历史会话 | 本设计 |
| L2 | 会话摘要索引 | chroma `chat_summaries`（摘要级语义） | 全部历史会话 | 规划中，摘要功能上线后复用同一召回通道 |

一句话口径：**L0 是"接着聊"，L1 是"翻旧账"，L2 是"记 gist"**。

## 1. 决议（R1–R7）

| # | 议题 | 决议 |
|---|------|------|
| R1 | 什么时候召回 | 由 LLM 在 understand 阶段**同时判断**：输出新增 `recall_query` 字段（空串 = 本轮不需要回忆）。指代/回忆类问题（"你记得吗""我说过""上次""我喜欢谁"）填改写后的检索词；普通问题填空串。**不每轮都搜**——检索词由 LLM 抽取实体（人、物、事件），不是原句照抄 |
| R2 | 召回通道 | `recall_query` 非空且 user_id 存在 → chroma `chat_history` 向量检索（`where={"user_id": str}`），top 5，注入生成 prompt。**零新增 LLM 调用**，本地向量检索毫秒级 |
| R3 | 注入形式 | system prompt 追加块，与"# 本轮话术参考"同级：`# 旧会话记忆\n（来自会话《标题》，3 天前）\n主人: ...\n小喜子: ...`——带来源和时间戳，模型可区分旧记忆与当前历史 |
| R4 | 无命中/失败 | 检索为空或抛错 → 不注入，正常回答（小喜子自己卖萌说不知道）。**绝不因召回失败打断主链路** |
| R5 | 降级通道 | bge 降级轮（LLM 不可用）跳过召回，保持现有行为 |
| R6 | 安全树洞 | emotion_alert 触发时，旧记忆注入照常（陪伴场景知道往事反而更暖），但树洞指令优先级高于一切记忆内容 |
| R7 | 匿名用户 | 跳过召回（历史无归属） |

## 2. 时序（接入 `_prepare_turn`）

```
understand(query, history)
    └→ RewriterQuestionResponse 新增 recall_query: str（默认 ""）
if recall_query and user_id and not degraded:
    hits = chroma 检索 chat_history（recall_query, user_id, top 5）
    memory_block = 格式化命中（来源会话标题 + 相对时间 + 内容）
_build_messages: system += "# 旧会话记忆\n" + memory_block
```

延迟账：新增耗时 = 一次向量检索（本地 chroma，毫秒级）。LLM 调用数不变，用户无感知。

## 3. Schema 与 prompt 改动（坑点提示）

1. `RewriterQuestionResponse` 增加 `recall_query: str = ""`——**必须给默认值**。否则旧 LLM 输出里没有这个字段，pydantic 校验直接失败，每轮都掉进降级通道——和当年"守卫条件写反"同级别的静默事故。
2. `understand_query` 提示词的 JSON 输出约定同步加字段说明：什么情况下填、填什么（检索词而非原句）、不需要时填空串。
3. 会话标题按命中行的 session_id 从 chat_sessions 批量查（与搜索接口同一套路）。

## 4. 验收用例

1. 会话 A 聊三轮："你好，我喜欢刘亦菲""她演过仙剑""我觉得她很有气质"；
2. 新建会话 B，问："你还记得我吗？我喜欢谁？"
3. 期望：小喜子答出"刘亦菲"并提及旧会话上下文（"主子您上回跟奴才念叨过…"）；
4. 反例：问一个从未聊过的话题（"我喜欢的车是什么"），不应幻觉——检索无命中时不注入，模型应老实说不记得。

## 5. 与搜索框的分工（防混淆）

| | 历史搜索框 | 跨会话召回（本设计） |
|---|---|---|
| 谁发起 | 人手工搜 | agent 自动判断 |
| 结果去向 | UI 列表展示 | 静默注入 prompt |
| 接口 | `POST /agent/sessions/search`（保留给人用） | 进程内直接查 chroma，**不走 HTTP**（少一次网络往返） |

## 6. 明确不做

- 召回结果注入 understand 的改写阶段（v1 只注入生成阶段；改写阶段引入历史会让改写变啰嗦）；
- 每轮无条件召回（省检索也防"错误记忆"污染——LLM 判需要才搜）；
- L2 摘要级召回（等摘要功能上线后，R2 的检索从只查 `chat_history` 扩展为并行查两个 collection，与搜索接口同构）。
