# 远程组网 + 本地 4090 推理方案（Embedding / Reranker / LLM）

> **状态**：规划（二期，一期 10.12 验收后实施）
> **目的**：ECS 只跑业务代码，模型推理全部下沉到本机 4090；ECS 经 Tailscale 内网调用
> **使用方式**：本文档同时是 Cursor 的实现依据——写代码时引用本文件的接口定义与降级策略
> **关联文档**：[架构演进.md ADR-003]、[v3.1 §7.9 降级思想]

---

## 一、背景与目标

### 1.1 要解决的问题

| 约束 | 现状 | 目标 |
|------|------|------|
| ECS 资源 | 只够跑业务代码，跑不动大模型 | 模型推理全部在 4090 本机 |
| Embedding 质量 | MiniLM-L12-v2 中文检索偏弱（384 维） | qwen3-embedding-4B（2560 维，CMTEB-zh 检索 77.03） |
| 检索质量 | 无 rerank | Qwen3-Reranker-0.6B 二精排 |
| 可用性 | 4090 是家庭单点 | ECS 本地小模型兜底，任何一环挂了 RAG 不死 |

### 1.2 选型结论（已定，不再讨论）

| 组件 | 主选 | 备选/兜底 | 明确不选 |
|------|------|-----------|----------|
| 组网 | **Tailscale** | ZeroTier | frp（无 ACL、配置繁琐） |
| Embedding（主） | **qwen3-embedding-4B**（4090） | bge-m3（省资源档） | M3E（非商用）、MiniLM（弱） |
| Embedding（兜底） | **bge-small-zh-v1.5**（ECS 本机 CPU） | 关键词映射 + 意图分类（零模型） | — |
| Reranker | **Qwen3-Reranker-0.6B**（4090） | 无 rerank | — |
| 推理服务框架 | **vLLM**（OpenAI 兼容 server） | FlagEmbedding + FastAPI（自包） | **Ollama**（无法代码级控制） |
| 本地 LLM（可选三期） | Qwen3-4B/8B-Instruct（4090，vLLM） | — | — |

**关于不用 Ollama 的决策**：需要 Python 代码级控制调用细节（自定义超时、批处理、降级路由、token 统计），Ollama 的封装不可控。vLLM 与 FlagEmbedding 均为 Python 原生。

## 二、总体架构

```
                        Tailscale 内网（WireGuard 加密）
┌──────────────────────┐        ┌──────────────────────────────┐
│  ECS（云服务器）       │        │  本机 4090（家用，常开）        │
│                      │        │                              │
│  XNCAgent (Python)   │  HTTP  │  ┌────────────────────────┐  │
│  ├─ Agent Core        │◄──────►│  │ vLLM Server (OpenAI    │  │
│  │   └─ EmbeddingClient│  :8001 │  │  兼容 /v1/embeddings   │  │
│  │      ├─ RemoteProv  │        │  │  /v1/rerank)           │  │
│  │      └─ LocalProv   │        │  │  · qwen3-embedding-4B  │  │
│  ├─ Go Gateway        │        │  │  · Qwen3-Reranker-0.6B │  │
│  │  └─ 商业化/用户/…    │        │  └────────────────────────┘  │
│  ├─ Chroma（向量库）   │        │  VRAM 估算：4B FP16 ≈ 8GB    │
│  └─ 兜底模型 bge-small │        │  + 0.6B reranker ≈ 1.5GB     │
│     （in-process）     │        │  24GB 显存富余，可再塞本地 LLM│
└──────────────────────┘        └──────────────────────────────┘
```

### 2.1 链路说明

1. **建库（离线，跑在本机）**：话术 md → 本机 qwen3-embedding-4B 批量嵌入 → Chroma 持久化目录 → rsync/同步到 ECS。
   建库不要求 ECS 能连 4090，避免建库被网络单点卡死。
2. **运行时查询（在线）**：ECS Agent Core → `EmbeddingClient` → 健康探测决定走 Remote（4090）还是降级路径 → 检索 → 若 Remote 可用，Top-10 再送 reranker 精排 → Top-3 拼 Prompt。
3. **降级**：Remote 连续失败 N 次 → 切 Local（ECS 本机 bge-small）或纯关键词路径 → 恢复后延迟切回。

### 2.2 一个关键数据约束（必背）

**不同模型的向量维度不同，同一 Chroma Collection 不可混用：**

| 模型 | 维度 |
|------|------|
| qwen3-embedding-4B | 2560 |
| bge-small-zh-v1.5 | 512 |
| MiniLM-L12-v2（现网） | 384 |
| bge-m3 | 1024 |

→ 兜底策略采用 **方案 A：降级不走向量检索**（见 §5.3），维度问题天然不存在。
   若将来坚持向量兜底，须建独立 fallback collection（方案 B），禁止混查。

## 三、网络层：Tailscale 组网

### 3.1 安装与组网（两边都要装）

```bash
# ECS（Ubuntu/Debian）
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --ssh   # --ssh 便于远程维护

# 本机 4090（Windows）
winget install tailscale
# 或官网下载安装包；登录同一账号
```

两台设备登录**同一 Tailscale 账号**（或同一 tailnet）后自动分配 100.x.x.x 内网 IP。
开启 MagicDNS 后可用主机名互访，如 `http://gpu-home:8001`。

### 3.2 必须做的三件事

1. **本机 4090 设为常开 + 禁止睡眠**：
   Windows：`powercfg /change standby-timeout-ac 0`；BIOS 里开 Wake-on-LAN（可选）。
2. **ACL 最小授权**（Tailscale Admin Console → ACL）：
   只允许 ECS 的 tag 访问 4090 机的 8001 端口，禁止其余设备互访。面试可讲"零信任内网"。
3. **Tailscale 只做组网，不做流量出口**：不要把 4090 机配成 exit node，ECS 出网走自己。

### 3.3 延迟与带宽预期（用于设超时）

| 指标 | 预期值 |
|------|--------|
| ECS ↔ 本机 RTT（国内家用宽带 + Tailscale 直连） | 10~40ms；若打洞失败走 DERP 中继 80~200ms |
| 家用宽带上行 | 30~100 Mbps，够传 embedding 向量 |
| qwen3-embedding-4B 单条短句（4090，vLLM） | < 20ms；批量 64 条约 100ms |
| 单次 RAG 查询总增加延迟 | < 100ms（可接受，主延迟在 LLM 生成） |

**超时基线**：EmbeddingClient 调 Remote 超时设 **2s**；连续 3 次失败触发降级；恢复探测连续 3 次成功才切回（防抖动）。

### 3.4 备选：ZeroTier

仅在 Tailscale 打洞持续失败（两边都是 NAT4/对称型）时启用：`curl -s https://install.zerotier.com | sudo bash`，组网逻辑相同。二选一，不要同时装两套。

## 四、4090 侧：推理服务（vLLM）

### 4.1 启动命令（本机，常驻）

```bash
# 安装（Python 3.10+，建议独立 venv/conda）
pip install vllm>=0.8

# Embedding + Reranker 服务（OpenAI 兼容协议）
vllm serve Qwen/Qwen3-Embedding-4B \
  --served-model-name qwen3-embedding \
  --port 8001 \
  --gpu-memory-utilization 0.45 \
  --max-model-len 8192 \
  --disable-log-requests &

# vLLM 对 reranker 的支持以官方文档为准；若版本不支持，
# 降级为 FlagEmbedding + FastAPI 自包（见 4.3）
```

显存预算：4B FP16 ≈ 8GB（util 0.45 ≈ 10.8GB 上限）；reranker-0.6B ≈ 1.5GB；
剩余 ~10GB 留给后续本地 LLM（三期，Qwen3-8B FP16 16GB 需调低 embedding 显存或量化）。

### 4.2 调用示例（OpenAI 兼容，与现有 LLM 调用代码同构）

```python
from openai import OpenAI

remote = OpenAI(
    base_url="http://gpu-home.tailnet-name.ts.net:8001/v1",  # 或 100.x.x.x
    api_key="EMPTY",            # vLLM 本地服务不设鉴权时占位
    timeout=2.0,                # 关键：内网调用也要设超时
)

resp = remote.embeddings.create(
    model="qwen3-embedding",
    input=["不想起床怎么办", "老板今天又画饼"],
    encoding_format="float",
)
vectors = [d.embedding for d in resp.data]   # 2560 维
```

**注意 instruction**：qwen3-embedding 对查询侧建议使用指令前缀
`"为这个句子生成表示以用于检索相关文章："`，文档侧不加。vLLM 请求里通过
`input` 直接拼接即可；FlagEmbedding 方式则走 `query_instruction` 参数。

### 4.3 降级实现：FlagEmbedding + FastAPI（vLLM 不支持 reranker 时用）

```python
# gpu_server.py —— 跑在 4090 本机，供 ECS 调用
from fastapi import FastAPI
from pydantic import BaseModel
from flag_embeddings import FlagModel, FlagReranker

app = FastAPI()
emb = FlagModel("Qwen/Qwen3-Embedding-4B", use_fp16=True)
rer = FlagRanker("Qwen/Qwen3-Reranker-0.6B", use_fp16=True)

class EmbedReq(BaseModel):
    texts: list[str]
    is_query: bool = False

class RerankReq(BaseModel):
    query: str
    passages: list[str]

@app.post("/embed")
def embed(req: EmbedReq):
    prefix = "为这个句子生成表示以用于检索相关文章：" if req.is_query else ""
    vecs = emb.encode([prefix + t for t in req.texts], convert_to_numpy=False)
    return {"vectors": [v.tolist() for v in vecs]}

@app.post("/rerank")
def rerank(req: RerankReq):
    scores = rer.compute_score([[req.query, p] for p in req.passages])
    order = sorted(range(len(scores)), key=lambda i: -scores[i])
    return {"order": order, "scores": scores}

# 启动：uvicorn gpu_server:app --host 0.0.0.0 --port 8001
# 注意：监听 0.0.0.0 仅因 Tailscale 接口复用网卡，ACL 已限制来源
```

## 五、ECS 侧：EmbeddingClient（Cursor 实现本接口）

### 5.1 接口定义（Python Agent Core 内新增 `xncagent/rag/embedding_client.py`）

```python
from abc import ABC, abstractmethod

class EmbeddingProvider(ABC):
    @abstractmethod
    def embed(self, texts: list[str], is_query: bool = False) -> list[list[float]]:
        """返回与 texts 等长的向量列表。实现方保证维度一致。"""

class RemoteProvider(EmbeddingProvider):
    """4090 via Tailscale，OpenAI 兼容 /v1/embeddings，超时 2s"""

class LocalProvider(EmbeddingProvider):
    """ECS 本机 bge-small-zh-v1.5，sentence-transformers in-process，无网络依赖"""

class CircuitBreaker:
    """连续失败 N=3 次开路；连续成功 M=3 次闭合。状态机见 5.3"""
```

### 5.2 检索编排（检索处只依赖抽象，不出现具体模型名）

```python
class EmbeddingClient:
    def __init__(self, remote: RemoteProvider, local: LocalProvider,
                 breaker: CircuitBreaker, use_rerank: bool = True):
        ...

    def embed_query(self, text: str) -> list[float] | None:
        """返回 None 表示降级，调用方走关键词/意图兜底路径"""
        if self.breaker.allow():
            try:
                v = self.remote.embed([text], is_query=True)[0]
                self.breaker.on_success()
                return v
            except Exception:
                self.breaker.on_failure()
        return None   # 不自动降级到 LocalProvider：维度不匹配，见 §2.2
```

### 5.3 降级决策表（面试口径：系统没有单点）

| 场景 | 行为 |
|------|------|
| Remote 正常 | embed → 检索 Top-10 → rerank 精排 → Top-3 |
| Remote 慢/超时/断连 | embed 返回 None → 短句关键词映射（已有）→ 未命中走 mDeBERTa 意图分类全库检索（已有） |
| 恢复 | 心跳探测（每 5s 一次 embed 固定短句）连续 3 次成功 → 切回 Remote |
| LLM（agicto）挂了 | 与 embedding 无关，走 v3.1 §9.4 静态模板话术（二期） |

**注意**：LocalProvider 是预留接口。启用它的前提是建了独立的 fallback collection（方案 B）。
一期上线采用方案 A（降级不走向量），LocalProvider 可先不实例化，代码留位。

### 5.4 心跳探测

```python
# 每 5s 一次；用固定短句（非真实查询）避免污染统计
HEARTBEAT_TEXT = "ping"
# 失败计数 >= 3 → 开路；成功计数 >= 3 → 闭合；开路期间探测照常进行
```

```yaml
embedding:
  provider: remote                    # remote | legacy（一期现网 MiniLM 库）
  remote:
    base_url: "http://100.x.x.x:8001/v1"   # Tailscale IP 或 MagicDNS 名
```

## 九、面试口径（从本文档可直接提炼）

1. **为什么 4090 放家里、代码放 ECS**：推理与业务解耦，ECS 成本最低配；GPU 资产复用。
2. **组网为什么选 Tailscale**：WireGuard 加密、ACL 零信任、打洞优先不走中继、与 ZeroTier 对比可一句话带过。
3. **家用单点怎么扛**：CircuitBreaker + 降级到关键词/意图路径——和 commercial_flow_mode 的开关文化一脉相承（"系统里没有任何组件是单点"）。
4. **为什么不用 Ollama**：需要代码级控制（超时、批处理、降级路由、token 统计）。
5. **选型怎么做的**：MiniLM（V1.0 资源约束）→ 评测发现中文检索短板 → 数据驱动切换 qwen3-embedding-4B（CMTEB-zh 检索 77.03，Apache 2.0 可商用，4B 与 8B 差距仅 ~1 分故选 4B），评测记录留档。

## 十、风险清单

| 风险 | 应对 |
|------|------|
| 家用宽带断网 / 停电 | 降级路径（§5.3）；本机 BIOS 设断电自启 + `powercfg` 禁睡眠 |
| Tailscale 打洞失败走 DERP 中继，延迟 200ms+ | 超时 2s 内仍可用；持续失败自动降级；必要时换 ZeroTier |
| vLLM 版本对 Qwen3-Embedding/Reranker 支持差异 | 实现时以官方文档为准；不支持 reranker 则走 §4.3 FlagEmbedding 服务 |
| 维度混用导致静默检索垃圾 | §2.2 硬约束 + 建库脚本断言维度与配置一致 |
| embedding 调用进同步链路放大故障面 | 超时 2s + 熔断 + 降级；心跳与真实查询共用通道但用固定短句 |
